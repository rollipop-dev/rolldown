# Hermes compatibility transforms

The legacy `RuntimeTarget::Hermes` branch in
`crates/rollipop_react_native_transform/src/lib.rs` groups supported transforms
with `swc_ecma_transformer::transform_hook` and `hook_pass`. Each group shares
one hook traversal:

1. Regular-expression compatibility and class static blocks.
2. Private-property brand checks, async functions/generators and object rest/spread.

Template-literal caching and class-property lowering run between these groups.
Static blocks must be lowered before class properties consume their generated
private fields. The second hook group must run after class-property lowering and
before class, parameter, destructuring and block-scoping transforms. Those
transforms also process code generated by the hooks.

Static-block lowering now runs before template caching. It moves existing
statements into private-field initializers; caching still visits their tagged
templates before class-property lowering.
The existing settings remain unchanged: only named captures, Unicode properties
and Unicode regexps are lowered; public fields use assignment and private fields
use spec storage; async lowering preserves function length. The async hook uses
the resolver's unresolved syntax context.

Use transformer 21.0.2, already in the lockfile, to share the existing SWC AST and
helper registry. Version 22 uses transforms-base 50, while this pipeline uses
transforms-base 49; using both would split helper registration and injection.

The hook API does not implement class-property lowering, despite exposing a
`class_properties` option. It also has no class, parameter, destructuring or
block-scoping options. Keep those passes until compatible hooks exist upstream.
`RuntimeTarget::HermesV1` retains its existing pipeline.

`tests/hermes_execution.rs` compares original and transformed program execution
in Node.js for interacting static blocks, regexp/template caches, private brands,
async generators, object rest/spread side effects, async super calls and loop
closures. These tests check JavaScript behavior, not execution in a Hermes runtime.
